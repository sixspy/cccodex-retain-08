# cc-retain-lab

CC_Codex 二期（26.11）**数据工程**产品线：**留存裁撤台**（FastAPI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**分区留存策略版本 → 到期扫描裁决 → 归档或销毁执行 → 策略与实物分区对账**

与现有六线正交（不是采集目录、ETL 管道、同步源、解析入库、编排流、种子摄取）。  
也不碰外仓常见指纹（Feed 归并 / 作业编排 / CDC 游标 / 质检签发 / 贴源-明细-汇总）。

## 领域

- **所属领域**：数据工程  
- **子方向**：数仓与数据湖（分区留存 / 裁撤闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、FastAPI、Uvicorn、SQLite |
| 前端 | 原生 JS 单页（全中文），青灰底 + 铜强调，顶栏导航（非绿侧栏克隆） |
| 测试 | pytest + httpx（本地秒级闭环，优先于 compose） |

## 基线已通主链

1. 现行留存策略（主题域 / 保留天 / 宽限天 / 到期动作）  
2. 实物分区列表（在线 / 归档 / 销毁，带宽限截止与可否销毁）  
3. 按基准日到期扫描 → 生成待执行裁决（扫描列表带「宽限拦截」计数）  
4. 单条裁决执行（归档写地址 / 销毁清零），**宽限期内销毁硬拦**  
5. 策略与实物对账报告（含生效宽限计数）

## 宽限保护闭环（retain-08 增补）

场景：到期扫描即裁撤，但分区**补采入库未完成**，需要宽限窗口，防止分区在宽限期内被提前毁掉。

- **形态择定：宽限登记快照表**（`grace_registrations`），不向分区状态机注入「宽限态」。
  分区仍是 在线/裁撤中/已归档/已销毁 四态，宽限是叠加在在线分区上的独立登记快照。
- 一条登记承载一次生命周期：`宽限中 → 已放行（补采核验）/ 已过期（截止未补采）/ 已关闭（人工）`。
- **宽限登记与裁决态对齐**：登记绑定未完成的「销毁」裁决；执行入口 `assert_destroy_allowed` 硬拦，
  提前毁即 409，分区一行不动；放行或过期后裁决自动恢复可执行。
- **串行锁写**：所有写路径经 `write_tx()`——进程内 `threading.RLock` + SQLite `BEGIN IMMEDIATE`，
  配合部分唯一索引 `ux_grace_open_per_partition`（同分区同时只许一条生效登记），
  缺锁的旁路双写在唯一索引处撞 `IntegrityError`，杜绝双写互盖。
- **补采任务可核**：补采状态（待补采/补采中/已补采）、任务号、核验时间、备注全部落库。
- 页面（策略详情 / 扫描列表 / 裁决队列 / 宽限登记 / 实物分区 / 对账）显示宽限截止与可否执行，
  生效态按基准日读时计算（已过截止但未处置的登记显示「已过期」且不再拦截）。

预留切口（未做，供后续功能题）：策略换版生效窗、重裁作废、批量失败闭互斥、跨域依赖冻结、归档回灌等。
